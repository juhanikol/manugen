2. How the inventory was made
Node bundles were inspected with esbuild input metafiles for ticket-demo.exe, embedding.exe, rag/rag.exe
and rag/rag-service.exe. js-yaml and markdown-it are included in rag.exe; they are not merely build tools.
UI client and server module graphs were captured separately from a Vite build of the release sources.
Only client modules and identified generated runtime/assets are listed below; SSR build output is not delivered.
Installed JavaScript versions were checked against the three lockfiles. devDependencies is not an exclusion.
esbuild, postject, resedit, sharp and Go compilation tools run during the build; their tool executables are
not copied into the application. Node/Go runtimes, Vite helper code, Workbox, generated CSS and fonts
are distributed material and are listed below.
MarkItDown: the converter (exe plus _internal) was matched file by file by SHA-256. The .spec,
Analysis/COLLECT/EXE/PYZ TOCs and Python 3.11.9 environment were inspected. Component versions below come
from matching TOC inputs to installed distributions. Full license texts were copied from those distributions
when present. Supplemental exact-version upstream/sdist texts are explicitly distinguished. A metadata classifier
or SPDX label is not a substitute for full terms, NOTICE content or corresponding-source obligations.
Go module versions were read from the actual ticket-export.exe with go version -m (Go 1.27.1).
All full license and NOTICE copies below retain their source bytes. Copyright excerpts are an index;
the complete files govern, including nested attributions. Missing excerpts are not a claim of no copyright.
Local application changes do not modify installed third-party package sources. Compilation/bundling
changes their output representation.
The installation package contains no knowledge content: the knowledge index rag/initial_index/index.sqlite is empty.
